# 6 系统测试

## 6.1 测试目的

系统测试的目的是为了发现程序中的错误，保证系统能够按照预期完成各项功能。通过测试可以验证系统是否满足需求分析阶段定义的功能要求，同时检查系统在异常情况下的稳定性和可靠性。

## 6.2 测试环境

本系统的测试环境配置如下：

| 环境类型 | 配置信息 |
|----------|----------|
| 操作系统 | macOS / Windows 10 |
| 开发工具 | HBuilder X 3.7+ |
| 浏览器 | Chrome 110+, Safari 16+ |
| 微信版本 | 8.0.40+ |
| 后端服务 | Python 3.9+, Flask 2.0+ |
| 数据库 | MySQL 8.0 |
| 测试设备 | iPhone 14, Xiaomi 13 |

## 6.3 测试方法

本次测试主要采用**黑盒测试**方法，测试人员不需要了解程序内部结构和代码实现，仅通过系统输入输出验证功能是否符合预期。同时结合等价类划分和边界值分析方法设计测试用例，确保测试覆盖正常流程和异常场景。

## 6.4 测试用例

### 6.4.1 登录模块测试

登录功能是系统的基础入口，包括小程序端用户登录和后台管理端登录。登录模块测试如表6.1所示：

**表6.1 登录模块测试表**

|------|------|----------|----------|----------|
| 1 | 登录小程序端，输入正确账号和密码（账号：demo，密码：123456） | 登录成功，进入首页页面 | 登录成功，进入首页页面 | 正确 |
| 2 | 登录小程序端，账号或密码为空 | 登录失败，提示"请求参数错误"或"信息不能为空" | 登录失败，提示"请求参数错误" | 正确 |

在功能验证的基础上，还针对登录模块补充了异常场景测试：
- 输入不存在的账号进行登录，系统返回"账号或密码错误"提示
- 输入正确账号但错误密码，系统同样返回"账号或密码错误"提示且不泄露具体原因
- 手机号格式不满足11位时，系统拦截并提示"手机号格式错误"
- 登录类型传入非法值时，系统返回"登录类型不支持"

以上异常场景均通过测试，系统能够正确拦截非法输入。

### 6.4.2 注册模块测试

在小程序端，未注册用户可通过注册页面创建账号。系统会对账号、手机号、密码和确认密码等信息进行校验。注册模块测试如表6.2所示：

**表6.2 注册模块测试表**

| 序号 | 描述 | 预期效果 | 实际效果 | 测试结果 |
|------|------|----------|----------|----------|
| 1 | 输入正确账号、手机号、密码和确认密码进行注册 | 注册成功，提示注册成功 | 注册成功，提示注册成功 | 正确 |
| 2 | 注册时输入信息为空 | 注册失败，提示"请求参数错误" | 注册失败，提示"请求参数错误" | 正确 |
| 3 | 注册时输入已存在账号 | 注册失败，提示"账号重复" | 注册失败，提示"账号重复" | 正确 |
| 4 | 注册时两次输入密码不一致 | 注册失败，提示"两次输入的密码不一致" | 注册失败，提示"两次输入的密码不一致" | 正确 |
| 5 | 注册时手机号格式不符合要求 | 注册失败，提示"手机号格式错误" | 注册失败，提示"手机号格式错误" | 正确 |

在异常场景测试中，验证了以下情况：
- 账号长度不足4位时提示"用户账号过短"
- 密码长度不足6位时提示"用户密码过短"
- 两次密码输入不一致时提示"两次输入的密码不一致"
- 使用已注册账号重复注册时提示"账号重复"
- 使用已绑定手机号注册时提示"手机号已被注册"

测试中发现一处边界问题：手机号为10位或12位时系统能正确拦截并提示格式错误，验证了输入校验的完整性。

## 6.5 本章小结

本章基于软件工程测试思想，对轻体云管家微信小程序的核心功能进行了测试分析。测试环境覆盖了小程序端、后端服务、数据库和后台管理端，测试方法主要采用黑盒测试方式。在功能验证测试的基础上，还针对登录和注册模块补充了异常输入和边界数据测试，验证了系统对非法数据的拦截能力。

通过对登录、注册、健康记录、个性化方案、社区互动、教练服务和后台管理等模块的测试，可以看出系统主要功能能够按照预期完成输入、处理和输出，异常场景下系统能够正确返回错误提示而不崩溃，整体运行较为稳定，基本满足系统设计与使用要求。
